# note への投稿

対象の章： $ARGUMENTS

## 前提

- `publish/note/NN_章題.txt` と、見出し画像 `publish/note/assets/NN_章題_header.png` があること。
  どちらかがなければ先に `/note-export` を実行する。それでも画像がなければ、公開に進まずユーザーに報告する。
- 作業はブラウザーで行う。ふだんは Claude のデスクトップ アプリの内蔵ブラウザーを使い、そのブラウザーのスキルを読んでから操作する。
  内蔵ブラウザーは、そのパソコンでデスクトップ アプリが開いていてオンラインのときだけ使える。つながらない場合は、アプリを開いてもらうよう依頼する。
  ユーザーが Claude in Chrome を指定したときは、そちらを使う。
- note には、使うブラウザーでユーザーがサインイン済みであることを前提とする。サインインが必要なら、ユーザーに依頼する（パスワードは Claude が入力しない）。
- **公開・予約・公開済み記事の編集は、外部に公開される操作である。** 文面をチャットで確定し、ユーザーの明示の承認を取ってから行う。
  ユーザーの依頼文に承認が含まれている場合（例：「予約まで進めてよい」）は、その範囲だけを行う。
- `publish/note/template.md` を必ず読み、「毎回の実施チェックリスト」を項目ごとに照合する。過去の記憶で確認済みにしない。

## 第 1 話の前に 1 回だけ：導入記事とマガジン

`novel.config.json` の `note.account_url`・`note.intro_url`・`note.magazine_url` のどれかが空なら、第 1 話の投稿の前にこれを行う。

0. `note.account_url` が空なら、note のアカウントのページ (プロフィールのページ) の URL をユーザーに尋ねて書く。推測で埋めない。

1. `publish/note/00_導入記事.md` の原稿（あらすじ、登場人物、制作について、マガジンの説明文）が書けているか確かめる。
   空の節があれば、正典から下書きを作ってチャットに示し、ユーザーの確認を取って原稿に書く。結末や真相は書かない。
2. 導入記事を note に下書き保存し、表示を確かめ、ユーザーの承認を取ってから公開する。
3. 連載マガジンを作り（説明文は原稿の「マガジンの説明文」）、導入記事を登録する。作成と登録の前にも承認を取る。
4. 導入記事とマガジンの URL を `novel.config.json` の `note.intro_url`・`note.magazine_url` に書き、`note.account_url` とあわせて commit・push する。
5. 第 1 話の書き出し（`publish/note/01_章題.txt`）を書き出し済みなら、末尾の案内の URL を埋め直す。

## 手順

### 1. 着手時の監査

- 前回公開した話の公開後作業（前話側の次話リンク、公開話の前話リンク、導入記事の一覧、マガジンの登録と順序）が済んでいるか、公開ページで確かめる。
  済んでいなければ、先にユーザーへ報告する。
- note の下書き・予約記事の一覧を開き、同じ話の重複がないか確かめる。

### 2. 文面をチャットで確定する

- 記事タイトル（`template.md` の形式）、前回までのあらすじ、末尾の案内（前話・次話・マガジン・導入記事・制作表記）をチャットに示し、ユーザーの確認を取る。
- 本文は `publish/note/NN_章題.txt` のとおりで、書き換えない。

### 3. 下書きを作る

1. note の新規記事を開き、タイトルと本文を入れる。
2. 第 2 話以降は、「前回までのあらすじ」の見出しと要約を引用ブロックにまとめる。
3. `＊` の行を note の区切り線に置き換え、`＊` を本文文字として残さない。区切り線の前後に余分な空段落を残さない。
4. 見出し画像（`publish/note/assets/NN_章題_header.png`、作り方は `publish/note/cover-image.md`）を設定する。
   ブラウザーのツールでファイルを添付できない場合は、画像の場所を示して、添付だけをユーザーに依頼する。
5. 下書き保存する。

### 4. 設定と表示を確かめる

`template.md` の「公開・予約設定」と「原稿・画像・書式」の項目を、実際の画面で確かめる。
プレビューで、一字下げ、空行、区切り線、引用ブロック、末尾までを原稿と照合する。

### 5. 承認を取って予約・公開する

- 予約日時（`novel.config.json` の `note.publish_schedule`、または依頼文の指定）と、年月日・曜日をユーザーに示し、承認を取る。
- 承認後に予約（または公開）を確定し、記事のタイトルと予約日時を読み直して確かめる。

### 6. 公開後の作業

予約時刻を過ぎ、新しい話の公開ページと URL を確かめてから行う。予約時点では完了扱いにしない。

1. 一つ前の公開記事を編集し、次話の予定案内を、新しい話のタイトルと実際の URL に置き換える。
2. 新しい記事の前話リンクが正しいことを確かめる。
3. 導入記事の公開済み各話の一覧に、新しい話を追加する。
4. 新しい話が連載マガジンに登録され、話数順に並んでいることを確かめる。
5. 編集画面の保存表示だけで完了とせず、各ページを公開ページで開き直して表示とリンク先を確かめる。
   `note.account_url` のアカウントのページでも、新しい話が公開されて並んでいることを確かめる。

公開済み記事の編集も、外部に公開される操作である。依頼文に承認が含まれていなければ、編集の前に承認を取る。

公開時刻に合わせて自動で行いたい場合は、ユーザーが求めたときだけ、公開時刻の数分後に動く定期タスクを提案する。
依頼文には、どの記事のどのリンクを書き換えるかを具体的に書く。設定した事実を、実行の成功と取り違えない。

### 7. 報告する

- 「予約設定の完了」と「公開後の導線更新の完了」を区別して報告する。
- `template.md` のチェックリストで「未完了」「対象外」にした項目を示す。
- マガジンや導入記事の URL が新しく決まったら、`novel.config.json` の `note` に書き、commit・push する。
