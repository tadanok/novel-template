# note 入稿用の書き出し

対象の章： $ARGUMENTS

## 前提

- `novel.config.json` の `note.start_after_all_chapters` が `true` なら、全章を書き終えるまで連載を始めない。
  書き出し自体は途中でも構わないが、公開判断はユーザーが行う。
- note のエディタは Markdown 記法をそのまま解釈しない。書き出しはプレーンテキストにする。
- 有料部分の区切りを入れるかどうかは、ユーザーの方針に従う（既定は全話無料）。

## 手順

### 1. 読み込む

- `chapters/NN_章題.md`（対象の章）
- `publish/note/template.md`（各話の定型フォーマット）
- `publish/note/00_導入記事.md`（表記と紹介文の統一のため。あれば）
- `.claude/rules/style-base.md` の「表記の既定」と `.claude/rules/style-genre.md` の「この作品の表記」
- `plot/outline.md`（章題と話数の対応）
- `log/continuity.md`（前回までのあらすじを書くため、前章の項）
- `novel.config.json`（作品名、話の呼び方、マガジンと導入記事の URL）

### 2. 表記を統一する

`style-base.md` の「表記の既定」と `style-genre.md` の「この作品の表記」に揃える。特に次を確かめる。

- 三点リーダーは `……`、ダッシュは `――`（それぞれ 2 つ重ね）
- 感嘆符・疑問符の直後に文が続く場合、全角スペースを 1 つ入れる
- 段落の先頭は全角スペース 1 字下げ。`「` で始まる会話文は下げない
- 括弧と引用符は全角に統一する

### 3. Markdown 記法を取り除く

- 見出し記号（`#`）を削除する。章題は定型フォーマットの所定位置に置く。
- 強調（`**` `*`）、箇条書き記号を削除する。
- 場面の区切り（`---` だけの行）は、前後に空行を 1 つずつ置いた `＊` 1 行にする。
  投稿時に `/note-publish` が note の区切り線に置き換える。

### 4. 定型フォーマットに流し込む

`publish/note/template.md` の枠に本文を入れる。
「前回までのあらすじ」は 2〜3 行で書く。前話までに公開済みの内容だけを使い、本話以降の展開を明かさない。第 1 話では省略する。

### 5. 書き出す

`publish/note/NN_章題.txt` に保存する。**元の `chapters/` は書き換えない。**

### 6. 見出し画像を用意する

`publish/note/cover-image.md` の方針に従う。

- `publish/note/assets/NN_章題_header.png` がすでにあれば、話数と章題が合っているかだけ確かめる。
- なく、`novel.config.json` の `cover_image`（全話共通の背景）があれば、背景に作品名・話数・章題を載せて 1280 × 670 px で作る。
  日本語の書体を用意できないなど、ここで作れない場合は、その旨と作り方（`cover-image.md` の手順 3）を報告する。
- 背景もなければ、見出し画像がまだないことを報告する（`/note-publish` は画像なしでは公開に進まない）。

書き出しと画像をまとめて commit・push する。

### 7. 報告する

- 字数：本文は `plot/outline.md` の最終字数（`chapters/` の値）。書き出したファイルの総字数（前書き・後書きの定型を含む）は `python3 tools/count_chars.py publish/note/NN_章題.txt`
- 変換した表記の件数と種類（例：三点リーダー 12 件、ダッシュ 4 件）
- 判断に迷って手を入れなかった箇所。ユーザーの目視確認を促す。
- 見出し画像の状態（作った／既存を確認した／作れなかった理由）

## やってはいけないこと

- 本文の内容を書き換えないこと。この工程は表記の変換のみを行う。推敲が必要なら `/polish` を先に実行する。
- 章を分割しないこと。1 章＝1 話とする。
