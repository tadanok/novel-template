# 章の執筆

対象の章： $ARGUMENTS

## 手順

### 1. 正典と文体ルールを読み込む（省略禁止）

以下をすべて読む。記憶で代用しない。`bible/archive/`・`plot/archive/`・`log/archive/` は改稿前の記録なので読まない。

- `.claude/rules/style-base.md` と `.claude/rules/style-genre.md`（**必ず明示的に読むこと**）
- `bible/` の全ファイル（`bible/archive/` を除く）
- `log/continuity.md`
- `plot/outline.md`（対象章の行と、前後の章の行）
- `plot/foreshadowing.md`
- `plot/open_questions.md`
- `novel.config.json`

構成改稿中（`docs/revision/` がある）なら、`docs/revision/revision_design.md`、
`docs/revision/chapter_revision_map.md` の対象章の項、`docs/revision/chapterNN_design.md`（あれば）も読む。

`docs/design/novel_design.md`（初稿の設計書）があれば、「情報開示の基準線」の対象章までの行と、対象章の役割を読む。

`log/continuity.md` にまだ章の記録がない（第 1 章を書く）ときは、`docs/canon-format.md` も読む。

### 2. 執筆前に確認する

以下に該当するものがあれば、**書き始める前にユーザーへ質問する**。
質問は選択肢と推奨をつけ、まとめて 1 回で聞く。

- 対象章の執筆に必要な情報が `plot/open_questions.md` に未確定として残っている
- 正典どうしに矛盾がある
- 前章からの申し送り事項が解決していない

該当しなければ、そのまま次へ進む。

### 3. 章の設計を先に示す

いきなり本文を書かず、以下を先に提示して合意を取る。

- 場面の並び（3〜6 場面程度）と、各場面の視点人物
- **各場面の目標字数**。合計が `plot/outline.md` の目安字数と一致すること。
  例：目安 7,000 字なら「導入 1,200／場面 2 2,200／場面 3 2,200／結び 1,400」のように配分する。
- 各場面で起こす「状況変化・新情報・人物関係の変化」
- この章で設置／進展／回収する伏線
- 章の作中日時

場面が多い章や構成改稿の章では、合意した設計を `docs/templates/chapter_design.md` の形で
`docs/design/chapterNN_design.md`（改稿時は `docs/revision/`）に残す。

### 4. 本文を書く

- 出力先：`chapters/NN_章題.md`（NN はゼロ埋め 2 桁）。章題が仮なら、`plot/outline.md` の進捗の備考に「仮」と書く。
- 1 行目は `# 第N章　章題`。場面の区切りは `---` だけの行。
- **手順 3 で配分した場面ごとの目標字数を守る。**
- 文体は `style-base.md` と `style-genre.md` に従う。特に「書く時点で防ぐこと」の 3 項目を守る。
- 人物の呼称は `bible/characters.md` の表記に統一する。
- 既存の章ファイルがある場合は、構成改稿中（`docs/revision/` がある）でなければ上書きしない。ユーザーに確認する。
  改稿中は書き直してよい。改稿前の本文は git の履歴に残る。

### 5. 字数を測る（省略禁止）

本文を書き終えたら、必ず実測する。目分量で判断しない。

```bash
python3 tools/count_chars.py chapters/NN_章題.md --target <目安字数> --scenes
```

- `--scenes` で場面ごとの字数が出る。手順 3 で配分した場面ごとの目標字数と比べ、薄い場面を特定する。
- **目安の 8 割を下回っていたら、そのまま次の手順へ進まず加筆する。**
  加筆は文章を薄く引き伸ばすのではなく、以下のいずれかで行うこと。
  - 手順 3 で配分したのに実際には薄くなった場面を、配分どおりまで書き込む
  - 会話の応酬を増やし、人物の反応・沈黙・動作を足す
  - 場面の前後（到着、退出、移動の間）を書いて呼吸を作る
- 加筆したら再度測り、8 割を超えるまで繰り返す。
- 目安を大きく超える場合（1.3 倍以上）は、冗長な説明が混ざっていないか確認する。
- 初稿の字数（最初に測った値）を控えておく。記録に書く。

生成モデルは字数目標に対して短く書く傾向が強く、しかも自己申告では気づけない。
**必ずスクリプトで実測すること。** `wc -m` はロケールによってバイト数を返すので使わない。

### 6. 別のエージェントで点検する

Agent ツールで `continuity-checker` を起動し、対象章と、それより前の全章を範囲として渡す。
このセッションで書いた章を自分で検証すると、見落としが起きる。

報告を受け取ったら、各指摘の根拠を本文と正典の原文で確かめてから、次の表でユーザーに示す。

| # | 深刻度 | 行 | 指摘 | 分類 | 修正案（推奨） |
| --: | :-- | --: | :-- | :-- | :-- |

分類は「本文を直す／正典を直す／判断が必要」のどれか。
「判断が必要」のものは選択肢と推奨を示す。ユーザーの確認を取ってから反映する（「すべて推奨どおり」でもよい）。
反映したら字数を測り直す。

起動できない場合は、その旨を伝え、新しいセッションで `/continuity-check` を実行するよう案内する。

### 7. 記録を更新する（ここまでで 1 タスク）

本文を書いただけで終わらせない。以下をすべて更新する。

- `log/continuity.md` に今章の項を追記する（書式は `docs/canon-format.md`）。字数はここには書かない。
- `bible/timeline.md` の「作中の進行」に該当章の行を追記する。
- 新登場人物・新設定・新しい呼称が出たら `bible/characters.md` または `bible/world.md` へ反映する。
- `plot/foreshadowing.md` の設置・回収状態を更新する。新しく張った伏線は、回収章を決めた上で追記する。
- `plot/outline.md` の「進捗」に、状態・初稿字数・最終字数・目安比・備考を書く。**字数を書くのはこの表だけ**。
- 確定した事項を `plot/open_questions.md` から消し込む。

### 8. commit・push して閲覧ページを更新する

1. 本文と記録をまとめて 1 つのコミットにし、push する。
2. `python3 tools/build_viewer.py` で閲覧ページを作り、公開する（手順はスクリプト冒頭の説明）。
   `novel.config.json` の `viewer.slug` が空なら新しく作り（title は「〈作品名〉 原稿閲覧」、icon は `book`）、
   slug・URL・`storage_key`（スクリプトが表示する値）を書き戻して commit・push する。

### 9. 完了報告

以下を簡潔に報告する。

- **実測字数と目安字数の比較**（例：「6,800 字／目安 7,000 字・97%」）
- 点検で直したこと
- 更新したファイル
- 次章への申し送り事項
- 閲覧ページの URL
- 次のセッションの依頼文（`docs/prompts/chapter-session.md` の「原稿チェックのセッション」か「章の執筆のセッション」を、この章に合わせて埋めたもの）
