# note 各話の定型フォーマットと公開の手順

`/note-export` はこの枠に本文を流し込み、`/note-publish` はこの手順とチェックリストで投稿する。
note の画面や設定の名前は 2026 年 11 月時点のもの。変わっていたら、ここを直す。

## 記事タイトル

```
〈作品名〉　第N話「章題」
```

- 作品名（`novel.config.json` の `title`）と話数を必ず入れる。マガジン一覧で順序が分かるようにするため。
- 全角スペースで区切る。「話」は `episode_label` に従う。

## 本文の構成

```
【前回までのあらすじ】
（2〜3行。ネタバレは前話までに公開済みの範囲に留める。第1話では省略）


（本文）


＊


（本文の続き）


────────────────

お読みいただきありがとうございました。
第N+1話は◯月◯日に公開予定です。

前話：（前話タイトルとURL。第1話では省略）
次話：（公開後に次話タイトルとURLを追記。最終話では省略）

この連載は下記のマガジンにまとめています。
（novel.config.json の note.magazine_url）

あらすじ、登場人物、制作方針は下記の導入記事にまとめています。
（novel.config.json の note.intro_url）

（制作表記。作者と AI の双方で推敲している旨を含める。文面は導入記事と揃える）
```

## 入稿時の注意

- 書き出しテキスト中の `＊` の行は場面区切りの位置を示す。投稿時に note の区切り線へ置き換え、`＊` を本文文字として残さない。区切り線の直前・直後に空段落を残さない。
- 第 2 話以降の「前回までのあらすじ」は、見出しと要約をまとめて note の引用ブロックに入れる。
- 見出し画像は 1280 × 670 px、10 MB 以内。`publish/note/cover-image.md` の方針に従う。
- 公開前に必ずプレビューで、一字下げと空行が意図どおりか確認する。
- ハッシュタグは `novel.config.json` の `note.hashtags` を共通で付ける。

## 公開前チェック

- 特徴的な台詞や表現、固有名詞が既存作品の創作的表現と類似していないか確認する。
- 見出し画像に実在人物、商標、既存キャラクターが意図せず含まれていないか確認する。
- 事実に基づく制度、手続、医療などの記述は、AI の出力だけに依存せず信頼できる資料で確認する。
- 導入記事へのリンクがあり、作品・制作についての表記を読者が確認できる状態にする。
- 前話・次話と連載マガジンへのリンクが正しいことを確認する。
- 公募への応募を予定する場合は、Web 公開済み作品と AI 利用作品に関する募集要項を公開前に確認する。
- 設定資料、初稿、改稿、Git 履歴を制作過程の記録として保管する。

## 連載導線の更新ルール

各話の末尾には、読者が投稿順に左右されず連載を読み進められるよう、次の導線を置く。

1. 前話のタイトルと URL（第 1 話では省略）
2. 次話のタイトルと URL（次話が未公開ならタイトルと公開予定日時。最終話では省略）
3. 連載マガジンの URL
4. 導入記事の URL

新しい話を公開した後は、次を一組の公開後作業として行う。

1. 一つ前の公開済み記事を編集し、次話の公開予定案内を、新しく公開した話のタイトルと URL へ置き換える。
2. 新しい記事の前話リンクが正しいことを確認する。
3. 導入記事の公開済み各話一覧へ、新しい話のタイトルと URL を追加する。
4. 新しい話が既存の連載マガジンに登録され、話数順に並んでいることを確認する。

予約投稿の設定だけでは、この公開後作業は完了していない。公開時刻を過ぎて新しい話の公開ページと URL を確認してから実施する。
次の話の準備を始める際は、最初に直前の公開話について上記 4 項目の完了を監査する。

編集後は、編集画面の保存表示だけで完了としない。一つ前の記事、新しい記事、導入記事、マガジンを公開ページで開き直し、表示文言とリンク先を確認する。

マガジンへの登録と並び順がすでに正しい場合は、再登録や並べ替えを行わない。
note 標準の記事下部にある「前の記事」「次の記事」は投稿順に基づくため、連載の主導線としては使わず、上記の明示的なリンクを優先する。

## 毎回の実施チェックリスト（必須）

作業開始時にこのテンプレートと `/note-publish` の手順を読み、対象話ごとに以下を照合する。
過去に設定した事実や会話の記憶だけで確認済みにしない。各項目は「確認済み」「未完了」「対象外」のいずれかとして扱い、未完了を残したまま全作業完了と報告しない。

### 着手時

- [ ] 前回公開話の公開後作業（前話側の次話リンク、公開話の前話リンク、導入記事一覧、マガジン登録・順序）を公開ページで確認する。
- [ ] 原稿は `chapters/NN_章題.md`、入稿用は `publish/note/NN_章題.txt`。対象の話数・章題を確認し、取り違えない。
- [ ] 既存の下書き・予約記事の有無を確認し、重複作成を避ける。

### 原稿・画像・書式

- [ ] 原稿本文は作者の承認なく推敲・省略・追加しない。書き出し時の表記変換は記録する。
- [ ] 第 2 話以降には、前話までの公開済み内容だけで作った 2〜3 行のあらすじを付ける。本話以降の展開を明かさない。
- [ ] あらすじの見出しと要約は note の引用ブロックにまとめる。
- [ ] 場面区切りは note の区切り線とし、`＊` や文字の `---` にしない。線の直前・直後に余分な空段落を残さず、前の話と同じ間隔にする。
- [ ] 段落、一字下げ、空行、本文末尾までを原稿と照合する。
- [ ] 記事タイトル、見出し画像の話数・章題、切り抜き範囲、文字の欠けを確認する。
- [ ] 末尾に謝辞、前話、次話、マガジン、導入記事、承認済みの制作表記を入れる。
- [ ] 未公開の次話は章題と公開予定日時で案内し、公開済みの次話は実際のタイトルと URL で案内する。導入記事等の紹介文で結末や善悪の評価を先に示さない。

### 公開・予約設定

- [ ] 無料・有料の区分、共通ハッシュタグ、既存マガジンへの追加を、実際の設定画面で確認する。
- [ ] コメント受付、記事の自動翻訳、AI 学習に関するデータ提供の設定を、作者の方針どおりか確認する（既定はいずれもオフ・許可しない）。
- [ ] X などへの自動連携・投稿をしない。その他の配信設定は承認済み方針を維持する。
- [ ] 予約日時は `novel.config.json` の `note.publish_schedule` を基本とし、対象の年月日・曜日を照合する。個別指定がある場合はそちらを優先する。
- [ ] 公開後作業を自動で行う定期タスクを設定している場合は、それが有効で、対象の公開日時をカバーしていることを確認する。
- [ ] 作者が本文、あらすじ、末尾の案内を確認できる画面を提示し、承認された内容で確定する。
- [ ] 確定後、対象記事のタイトルと予約日時または公開状態を読み直して確認する。

### 新しい話の公開後

- [ ] 実際に公開された記事を開き、タイトル・本文・画像・前話リンクを確認する。
- [ ] 一つ前の公開記事の次話予定案内を、新公開話のタイトルと実 URL へ置き換え、公開ページで表示とリンク先を確認する。
- [ ] 導入記事の公開済み各話一覧へ新公開話を追加し、公開ページで確認する。
- [ ] マガジンへの登録と「導入記事 → 第 1 話 → 第 2 話…」の順序を確認する。
- [ ] 最新話の次話予定日時が次の予定と一致しているか確認する。
- [ ] 「予約設定完了」と「公開後の導線更新完了」を区別して報告する。後者は公開前には完了扱いにしない。

予約時点で公開後作業が残る場合は、その項目を明示する。自動実行する仕組みを実際に設定していない限り、公開時刻に自動でリンク更新できると約束しない。
